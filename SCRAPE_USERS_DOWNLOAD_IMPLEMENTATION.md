# Scrape Users Download Button Implementation\n\n## Overview\nAdded a download button for `scrape_users` jobs on the Jobs page, mirroring the existing functionality for `group_monitor` jobs.\n\n## Files Modified\n\n### 1. Backend: `backend/scrape_user_id/router.py`\n**Changes:**\n- Added imports: `Query`, `StreamingResponse`, `Job`, `os`\n- Replaced the old `/download` endpoint that accepted `filename` parameter\n- Implemented new `/download` endpoint that accepts `job_id` parameter\n\n**Key Features:**\n- Validates job ownership and user permissions\n- Validates job type is `scrape_users`\n- Searches for the corresponding CSV file in `/app/job_results/`\n- Uses the most recently created file matching the account phone number pattern\n- Returns 404 with appropriate error message if file not found\n- Streams the CSV file with proper headers for download\n\n**New Endpoint:**\n```python\n@router.get(\"/download\")\ndef download_csv(\n    job_id: int,\n    db: Session = Depends(get_db),\n    current_user: User = Depends(plan_based_dependency(\"scrape\"))\n)\n```\n\n### 2. Frontend: `frontend/src/pages/Jobs.tsx`\n**Changes:**\n- Updated `handleDownload()` function signature to accept `jobType` parameter\n- Added logic to route to correct endpoint based on job type:\n  - `group_monitor` → `/api/group-monitor/download`\n  - `scrape_users` → `/api/scrape-users/download`\n- Updated default filename logic to use appropriate names for each job type\n- Updated download button condition to include `scrape_users`:\n  ```jsx\n  {(job.job_type === 'group_monitor' || job.job_type === 'scrape_users') && (\n    <IconButton\n      onClick={() => handleDownload(job.id, job.job_type)}\n      size=\"small\"\n      title=\"Download results\"\n    >\n      <Download />\n    </IconButton>\n  )}\n  ```\n\n## How It Works\n\n### User Flow\n1. User creates a scrape users job on the \"Scrape Users\" page\n2. Job appears in the \"Jobs\" page with status \"pending\"\n3. Once job completes (status = \"completed\"), a **Download button** appears\n4. User clicks the Download button\n5. Frontend calls `/api/scrape-users/download?job_id={id}`\n6. Backend retrieves the corresponding CSV file from disk\n7. File is downloaded to user's computer\n\n### File Naming Convention\nScrape user results are saved as:\n```\n/app/job_results/participants_{phone_number}_{timestamp}.csv\n```\n\nWhen downloading, the endpoint finds the most recent file matching the account's phone number.\n\n## Testing\n\n### Test Coverage\n✅ **Endpoint Validation**\n- Endpoint exists and is accessible\n- Returns 404 for non-existent jobs\n- Returns 403 for unauthorized requests\n- Validates job_id parameter is required\n\n✅ **Security**\n- Job ownership verification (job must belong to current user)\n- Job type verification (must be 'scrape_users')\n- Authentication required (Bearer token)\n\n✅ **UI Rendering**\n- Download button appears for group_monitor jobs ✓\n- Download button appears for scrape_users jobs ✓\n- Download button correctly calls the appropriate endpoint\n- Proper error messages when download fails\n\n### Running Tests\n```bash\n# Verify endpoint and UI logic\npython test_scrape_download.py\n\n# Run integration tests\npython test_integration_scrape_download.py\n```\n\n## Error Handling\n\n| Status | Scenario | Message |\n|--------|----------|----------|\n| 200 | Success | CSV file streamed |\n| 404 | Job not found or wrong type | \"Job not found or not owned by user\" |\n| 404 | File not created yet | \"Result file not found. Job may still be processing.\" |\n| 403 | Not authenticated | Authentication required |\n| 422 | Missing job_id parameter | Query parameter validation error |\n\n## API Compatibility\n\nThe implementation follows the same pattern as `group_monitor` download:\n\n**Group Monitor Download:**\n```\nGET /api/group-monitor/download?job_id=1\n```\n\n**Scrape Users Download:**\n```\nGET /api/scrape-users/download?job_id=1\n```\n\nBoth return:\n- Content-Type: text/csv\n- Content-Disposition: attachment; filename=...\n- 404 if file not found\n\n## Deployment Notes\n\n✅ Changes are backward compatible\n✅ No database schema changes required\n✅ No new environment variables needed\n✅ Works with existing Docker setup\n\n## Future Improvements\n\n- Consider caching the file path in the database for faster lookups\n- Add ability to download partial results while job is still running\n- Implement file expiration policies for old result files\n"
